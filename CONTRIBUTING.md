# Contributing

**Status:** active template policy
**Responsible role:** contributor
**Update when:** development workflow or verification entry points change.

Use an ExecPlan for material changes as described in [AGENTS.md](AGENTS.md). Keep changes small, add focused tests, run the documented verification commands in the container, and report failures or blocked checks honestly. Do not commit credentials, generated runtime data, or unreviewed lockfile changes.

Use GitHub Issues and pull requests for review. A pull request must identify its requirement/plan, validation evidence, limits, and deferred work. See [docs/workflows/DEVELOPMENT_WORKFLOW.md](docs/workflows/DEVELOPMENT_WORKFLOW.md).
