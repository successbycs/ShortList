# Definition of Ready

**Status:** active | **Owner:** change owner | **Update:** planning policy changes.

A material change has an outcome, scope/non-goals, owner, acceptance evidence, affected boundaries, and known decisions or questions before implementation begins.

An Issue is ready to build when it states:

- a concise outcome and non-goals;
- the files or areas in scope;
- acceptance evidence and the exact checks that prove it ("Done when"); and
- planning evidence appropriate to the work's risk, as described in
  [Development Workflow](../workflows/DEVELOPMENT_WORKFLOW.md#planning-evidence-by-work-size).

Work proceeds from Chris's request and the Issue's actual dependencies. Labels
do not make work ready or start any automation. GitHub Assignees remain human
accountability. How the work is then reviewed and merged is in
[AGENTS.md](../../AGENTS.md#review-and-merge).
